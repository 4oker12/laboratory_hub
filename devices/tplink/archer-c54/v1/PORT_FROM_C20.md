# Archer C54 (EU V1): перенос из RouterLab C20 v5

Статус: **подготовлен исследовательский адаптер состояний**. Это не готовая авторизация или автоматическая настройка C54.

## Основа в существующем проекте

Источник: `extensions/tplink-c20/independent-session/` из ветки `feat/routerlab-mobile-c20-wifi-quicksetup`.

| Подсистема C20 | Повторное использование | Почему |
| --- | --- | --- |
| `flow.js` / `classifyNative()` | Да, через `flow-bridge.js` | FIRST_CONNECT / LOGIN / QUICK_SETUP / WIFI_EDITOR сохраняются |
| `flow.js` / `cleanWifi()` | Да | Общие ограничения SSID и паролей |
| `flow.js` / `quickStepFromSignals()` | Да | ISP_WAN / VLAN_DEFAULTS / WIRELESS / FINISH |
| `setup.html`, `setup.css` | Можно переиспользовать дизайн | UI отделён от CGI |
| `setup.js` | Требует параметризации | Действия пока C20-специфичны |
| `crypto.js` | Не подключать до доказательств | Схема C54 не подтверждена |
| `protocol.js` | Только как эталон для diff | CGI OID, стеки, формат SET должны быть доказаны |
| `background.js` | Нельзя копировать целиком | Cookie, RSA, /cgi_gdpr, ошибки iPhone и хост зашиты под C20 |
| `tests/*` | Переносить инварианты | Не считать mock аппаратной проверкой |

## Артефакты

- `flow-bridge.js`: использует существующий `C20Flow`, но разрешает распознавание только `Archer C54` / EU / V1.
- `tests/flow-bridge.test.cjs`: проверяет, что состояния совпадают с C20, неподходящая модель блокируется и нет записи/защищённого чтения.
- `tools/tplink-c54/inspect-stock.py`: автономно скачивает официальный ZIP и ищет признаки CGI в образе и LZMA-потоках.
- `.github/workflows/routerlab-archer-c54-firmware.yml`: выполняет тесты и публикацию только отчётов.

## Важные границы

- Статическая прошивка C54 EU V1 1.15.0: официальный архив успешно получен.
- Binwalk показывает IMG0 (VxWorks) и LZMA-потоки, но не SquashFS; требуется декодирование вложенных ресурсов.
- Нельзя считать отсутствие строк в сжатом BIN доказательством отсутствия CGI.
- Никаких пакетов C54 от RouterLab пока не отправлено; физического теста авторизации/записи нет.
- Настройки C20 и ограничения iOS (первый POST, cookie, нативная кнопка) **не наследуем** без отдельных доказательств.
- Сборка из GitHub-ветки не предназначена для установки вместо C20-версии.

## Проверки перед первой записью на C54

1. Подтвердить маркировку на наклейке: C54, V1, EU и версию из веб-панели.
2. Снять обезличенный HAR или найти vendor JS: URL, метод, имя поля, алгоритм шифрования, статус сессии.
3. Проверить схему LOGIN и прочитать текущие параметры WAN и обоих WLAN через подтверждённые вызовы.
4. Привязать новый C54 transport/protocol adapter и выполнить мок-тесты без записи.
5. Только на тестовом устройстве после резервной копии: CREATE_ADMIN → DHCP WAN → Wi-Fi → одно сохранение → повторное чтение; отдельно проверить потерю соединения и восстановление.
6. Не отправлять повторно LOGIN или SET после сетевого сбоя без проверки фактического результата.

**Цель:** общий RouterLab UI и wizard-flow; разные модели предоставляют собственные login/session/read/write contracts.
