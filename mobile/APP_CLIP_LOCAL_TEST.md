# RouterLab App Clip — локальный тест по QR на iPhone 12

**Состояние:** подготовлен исходный код и компиляция App Clip; настоящий запуск через Local Experience на физическом iPhone **не подтверждён**. Компиляция `.ipa` с `CODE_SIGNING_ALLOWED=NO` не заменяет Apple-подпись и регистрацию App Clip.

## 1. Что уже есть

- Полноценный RouterLab iOS, который физически обнаружил Netis N2 на `192.168.2.1`, принял пароль администратора и прочитал WAN/WLAN/IGMP.
- Отдельный App Clip target `RouterLabAppClip` на общей базе SwiftUI, WKWebView и CGI-адаптера.
- Bundle ID App Clip: `dev.routerlab.mobile.Clip`; родительского приложения: `dev.routerlab.mobile`.
- Для App Clip заводская запись настроек выключена. Авторизация и чтение остаются, но изменение SSID и Quick Setup в настроенном состоянии не реализованы и не показываются.
- В Actions собираются неподписанные iPhone и Simulator артефакты с App Clip.

## 2. Что НЕ следует делать с IPA из Actions

`RouterLabAppClip-UNSIGNED-device.ipa` — **заготовка для подписи**, не готовый App Clip для Local Experience. Просто скопировать IPA в телефон или установить обычный родительский RouterLab через Sideloadly недостаточно, чтобы iOS зарегистрировала App Clip.

Apple описывает два корректных пути к кэшу App Clip на устройстве:

1. Собрать и запустить **схему RouterLabAppClip** на iPhone через Xcode под командой разработчика.
2. Сначала архивировать родительское приложение, затем экспортировать **отдельный подписанный App Clip IPA** для Development/Ad Hoc, установить его через Xcode Devices and Simulators.

Возможность подписать настоящий App Clip через Sideloadly с бесплатным Apple Account **не подтверждена**. При ошибках provisioning/entitlements не удалять рабочий RouterLab: сохранить его как контрольный вариант.

Не присылать в чат Apple ID, коды 2FA, сертификаты, приватные ключи или пароль Netis. Не добавлять их в GitHub.

## 3. Поля с твоего скриншота Local Experience

После того как **подписанный App Clip действительно находится в кэше iPhone**:

Настройки iPhone → Developer → Local Experiences → Register Local Experience.

| Поле | Значение для теста |
|---|---|
| URL PREFIX | `https://example.com/connect` |
| BUNDLE ID | `dev.routerlab.mobile.Clip` |
| Title | `RouterLab` |
| Subtitle | `Проверка домашнего роутера` |
| Action | `Open` |
| Choose Photo | Любое нейтральное изображение для тестовой карточки |

Нажать **Save**. Значение `example.com` — **только тестовый HTTPS-префикс** для локально зарегистрированного опыта. Оно **не является** сайтом RouterLab и не даёт публичный доступ абонентам. Без регистрации Local Experience этот URL ведёт на сторонний сайт, а не в RouterLab.

## 4. Создание QR

Тестовый QR хранит **только HTTPS-ссылку**, без IP роутера и паролей.

```powershell
py -m pip install "qrcode[pil]"
py mobile/scripts/generate_local_experience_qr.py --url https://example.com/connect --out routerlab-appclip-local-qr.png
```

Или скачать `RouterLab-AppClip-Local-QR` из артефактов GitHub Actions этого PR. Покажи QR на экране Windows и сканируй камерой iPhone (не пытайся сканировать на том же экране телефона).

Убедись, что:
- подписанный App Clip установлен/закэширован;
- Local Experience сохранён;
- на iPhone есть интернет для загрузки интерфейса App Clip, если это необходимо;
- после открытия iPhone подключён к Wi-Fi **Netis**, а не к верхнему TP-Link;
- запрошенный доступ к локальной сети разрешён.

## 5. Ожидаемый маршрут

QR → карточка App Clip с заголовком RouterLab → **Open** → собственный экран поиска → `Netis N2` по `192.168.2.1` → пароль администратора → реальные данные WAN, 2,4 ГГц, 5 ГГц, IGMP.

Успех **не** равен простой отрисовке карточки. Зафиксировать отдельно:
1. Появилась ли карточка.
2. Открылся ли **App Clip**, а не обычный RouterLab.
3. Успешен ли запрос CGI с локального origin.
4. Успешна ли авторизация.
5. Совпадают ли SSID с настоящими настройками.

Никаких записей в конфигурацию роутера в этом эксперименте.

## 6. Диагностика

- **Нет карточки App Clip:** проверить точный Bundle ID, URL PREFIX, подписанный кэш, тип профиля Development/Ad Hoc/TestFlight. Обычный неподписанный IPA не подходит.
- **Открывается Safari:** нет работающего локального опыта/кэша или QR обрабатывается как обычная HTTPS-ссылка.
- **Открывается основной RouterLab:** наличие полного приложения влияет на выбор запуска; для App Clip-проверки использовать тестовый сценарий без установленного родительского приложения, предварительно сохранив контрольную версию.
- **Нет доступа к роутеру:** разрешение Local Network, сеть Wi-Fi, адрес, ответ Netis по CGI, питание роутера.
- **Пароль не принят:** проверить только код отказа и результат `login.cgi`, никогда не записывать пароль в лог.

Apple: https://developer.apple.com/documentation/appclip/testing-the-launch-experience-of-your-app-clip

## 7. Переход к реальной ссылке для абонента

Демонстрационный QR не является массовым способом распространения. Чтобы абонент без установленного приложения мог получить App Clip по HTTPS, нужны Apple Developer Program, подписанное и загруженное приложение с App Clip, App Store Connect App Clip experience и публикация/одобрение. Для **собственного** домена провайдера дополнительно нужны Associated Domains и AASA на сайте.

Apple генерирует стандартную публичную ссылку App Clip при регистрации default experience; её можно использовать без своего домена после нужных этапов публикации. До этого нельзя обещать публичное открытие по ссылке.

**Контрольная точка:** перейти к полевому тесту только после получения корректно подписанного и закэшированного App Clip на iPhone.
