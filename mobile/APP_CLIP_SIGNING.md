# RouterLab App Clip — no-cost-first signing and QR test gate

Updated: 2026-11-03. This is a **prepared** optional signing path, not a successful device test.

## Decision and hard constraints

- The default workflow remains \`.github/workflows/routerlab-mobile-ios.yml\`: browser mocks, unsigned Simulator/iPhone builds, embedded App Clip structural checks, experimental standalone unsigned Clip package and local-experience QR.
- No Apple Developer Program enrollment, subscription, credit card, App Store Connect enrollment, paid service, Apple login or real device configuration is authorized.
- Do not circumvent Apple signing or App Clip entitlements, expose signing material, or treat Sideloadly installation of the full app as successful App Clip invocation.
- Keep the already physically verified Netis N2 read-only checkpoint intact. No factory reset, network changes or blind CGI SET commands.
- The separate \`.github/workflows/routerlab-appclip-signed.yml\` is MANUAL ONLY and fails closed until the Apple signing inputs below already exist.
- The GitHub repository is PUBLIC. Signed artifacts are not uploaded by default. For privacy, prefer a private repository or a trusted private distribution channel for device builds; treat any opted-in public GitHub Actions artifact as potentially accessible to repository readers.

## Required inputs, only if already available

For automatic Development/Ad Hoc signing in GitHub Actions you must supply:

| GitHub Actions configuration | Contents |
|---|---|
| Repository variable \`ROUTERLAB_APPLE_TEAM_ID\` | 10-character Apple Team ID |
| Secret \`ROUTERLAB_IOS_TEST_DEVICE_UDID\` | UDID of the test iPhone; checked against both profiles and never printed |
| Secret \`ROUTERLAB_IOS_P12_BASE64\` | base64 of Apple Development / Distribution certificate WITH PRIVATE KEY in .p12 form |
| Secret \`ROUTERLAB_IOS_P12_PASSWORD\` | password for the .p12 file |
| Secret \`ROUTERLAB_IOS_PARENT_PROFILE_BASE64\` | original .mobileprovision profile for \`dev.routerlab.mobile\` |
| Secret \`ROUTERLAB_IOS_CLIP_PROFILE_BASE64\` | original .mobileprovision profile for \`dev.routerlab.mobile.Clip\` |

Use two distinct, unexpired profiles issued for the same Team ID and including the iPhone test device UDID. Both need to match the chosen Development or Ad Hoc method. Profiles must be generated by Apple, never fabricated. Never paste Apple credentials, certificates, private keys, UDIDs or provisioning profiles into issues/chat/logs or commit them.

If these inputs are unavailable, **do not attempt signed workflow**. The unsigned GitHub Actions path continues to provide reliable evidence that Swift/iOS and App Clip source code compile.

### Signing workflow

When the signed workflow exists on the repository's DEFAULT branch (GitHub requires this for \`workflow_dispatch\` visibility), use GitHub Actions → **RouterLab App Clip signed device archive (manual)** → Run workflow. Select \`development\` (normally the first physical test) or \`ad-hoc\`, and leave **upload_signed_ipa=false** unless an explicit secure artifact transfer is necessary and approved.

The runner validates two exact App IDs, Team ID, expiration, development vs Ad Hoc method, and the test iPhone UDID in both profiles; creates temporary keychain, imports existing certificate/profiles; generates a temporary signed XcodeGen project; archives the full app with embedded App Clip; exports IPA; checks codesign and embedded bundle IDs; removes temporary signing material.

A successful signed export is **not** a successful iPhone App Clip launch.

### Testing real QR invocation

Apple's local experience requires a correctly **signed and cached** App Clip, not merely an unsigned \`.ipa\` or a full app installed with Sideloadly. For an Apple-supported test, build and run the App Clip scheme on a connected device in Xcode, OR export a correctly signed **separate** App Clip IPA for Development/Ad Hoc and install it through Xcode Devices and Simulators, then register Settings → Developer → Local Experiences on the iPhone. The standalone IPA repack produced by this workflow is EXPERIMENTAL, not guaranteed equivalent to an Xcode-exported separate App Clip. Confirm using actual iPhone evidence.

Example fields for a **local-only** test: URL Prefix \`https://example.com/connect\`, bundle ID \`dev.routerlab.mobile.Clip\`, title \`RouterLab\`, action \`Open\`. The \`example.com\` URL is a placeholder used ONLY with a registered Local Experience and is not a public RouterLab domain. Public distribution requires a separate Apple release path; out of scope.

Evidence checklist:
1. Properly signed App Clip was installed/cached.
2. iPhone QR scan showed actual App Clip card.
3. App Clip process launched (not Safari and not full RouterLab).
4. Local-network permission and real Netis CGI read succeeded.
5. If needed, authorized login succeeded, then WAN/WLAN/IGMP readback matched actual router.
6. No configuration write or reset occurred.

If any gate fails, report exactly where, with sanitized error/status codes only. Do not claim success by extrapolating from CI.

### Free fallback

Apple allows testing your own apps with a free Apple Account using Xcode on a Mac. This is distinct from automated remote GitHub Actions signing and has personal-team and entitlement limitations. With only Windows + iPhone + cloud GitHub Actions and without existing certificates/profiles, a reliable, Apple-supported **real QR Local Experience** is not currently established. Do not buy a membership automatically or promise a bypass.

Official reference: https://developer.apple.com/documentation/appclip/testing-the-launch-experience-of-your-app-clip
