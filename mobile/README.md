# RouterLab Mobile v0.3 — простая настройка по ссылке (исходный прототип)

## Идея

Абонент получает ссылку, подключается к Wi-Fi роутера и нажимает одну кнопку. RouterLab определяет устройство и запускает **только подтверждённый на данной модели и прошивке** сценарий; после изменений должна быть проверка фактического состояния WAN/Wi-Fi.

Это целевой сценарий, а **не текущая готовая автоматическая настройка**.

## Реализовано в v0.3

- Простая страница запуска `RouterLab-Launcher.html`: основная кнопка, технический ввод IP скрыт.
- iOS SwiftUI + WKWebView c загрузкой штатной локальной страницы. Адрес можно передать через `routerlab://open?host=192.168.0.1` в уже установленное приложение.
- Однокнопочный read-only preflight: загрузка страницы, распознавание `Archer C20 v5` и `Build 200821` по разрешённым публичным признакам интерфейса, безопасный отказ на неизвестной прошивке.
- Параметры и техническое воспроизведение прежнего DOM-сценария сохранены в режиме «Для специалиста».
- Нельзя выдать «настройка завершена», пока нет реального read-after-write для WAN и Wi-Fi; автоматических изменений в пользовательском режиме v0.3 нет.
- Запросы и сценарии выполняются локально внутри WebView. Приложение не пересылает пароли на сервер и не принимает команды/пароли через внешнюю ссылку.

## Границы подтверждения

**Физически подтверждено 26.10.2026:** Router-Origin Overlay в Chrome на Archer C20 v5, вход с существующим админ-паролем, защищённое чтение WLAN и успешное изменение SSID.

**Не подтверждено:** полный заводской Bootstrap, WAN apply, URL-based запуск на iPhone, Xcode build, поведение WKWebView с TP-Link штатной сессией, автоматическое переподключение при смене Wi-Fi, App Clip.

v0.3 — рабочий исходный прототип для проверки iOS-транспорта и распознавания устройства; не использовать для массовой настройки абонентов.

## Доставка пользователю одной ссылкой

- **Сейчас:** Custom URL scheme `routerlab://` открывает приложение **только после установки**. HTML launcher нужно разместить на HTTPS-сервере. Файл в ZIP не является опубликованной ссылкой.
- **Цель для iPhone без предварительной установки:** Apple App Clip. Для реального запуска требуются отдельный App Clip target, подписанный бинарник, App Store Connect/публикация и конфигурация invocation URL. Наличие сайта само по себе не запускает App Clip.
- **Android:** отдельный WebView/Deep Link или Instant Experience, с проверкой платформенных требований.

## Как собрать iOS-прототип

1. Открыть `RouterLabMobile.xcodeproj` в Xcode на macOS.
2. Указать собственный Team/Bundle ID для подписания.
3. Установить на iPhone (iOS 16+) через Run или организовать разрешённое распространение.
4. Подключиться к Wi-Fi тестового Archer C20, открыть приложение или `routerlab://open?host=192.168.0.1`.
5. Нажать «Проверить роутер», посмотреть модель/состояние. Никакие WAN/Wi-Fi параметры этой кнопкой **не изменяются**.

Существующий режим «Для специалиста» позволяет записывать/воспроизводить действия в штатном UI, но завершение кликов не является доказательством применения конфигурации. Не сбрасывать тестовый роутер до отдельного согласованного теста Bootstrap.

## Проверки в текущей среде

```bash
python -m unittest discover -s tests -v
```

15 Chromium tests покрывают простой launcher, распознавание модели по DOM, отсутствие экспорта паролей, отказы на неизвестных страницах и прежний технический replay. Это не iOS-компиляция и не физический тест.
